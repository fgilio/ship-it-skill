One tool call writes the run file: a Write or Edit whose `file_path` is the run file, or a shell command whose redirect, `tee` or `open(` targets it as `~/.claude/...`, `$HOME/.claude/...` or under the run's absolute home. The run's home is the parent of the session's `cwd` in the trace's first line, so a `.claude` under any other prefix fails at `~/.claude/ship-it/runs/acme-books/invoices/<plan slug>.json`, in JSON or in a script's dictionary, with `"mode": "merge-ready"`. In it the PDF PR (its title names PDF) has a `depends_on` entry on the log PR (its title names the log) with `"needs": "evidence"`, and the log PR's `depends_on` is empty. Each PR is found by its title, and its `depends_on` read wherever it sits in the PR, so key order does not matter. The eval sandbox refuses every write under `~/.claude`, so the grader reads the write the skill made, from the trace, and not the file.
